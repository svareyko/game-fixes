# S.T.A.L.K.E.R. 2 — вылет GPU `DXGI_ERROR_DEVICE_HUNG` на RTX 5090 (Async Compute)

Игра вылетает на рабочий стол через несколько минут после начала игры — раз за разом в одной и той же
области — с отчётом «GPU crash». Сам драйвер после этого работает нормально. На описанном ниже ПК причину
нашли в собственной работе игры на GPU, которая идёт в очереди async compute; **отключение Async Compute
в графических настройках игры остановило вылеты**.

[English version](README.md) · [Как это нашли](docs/how-it-works.ru.md)

## Это твой случай?

Всё перечисленное одновременно:

- Игра закрывается, и открывается краш-репортёр Unreal с надписью **`GPU Crash dump Triggered`**.
- `Stalker2.log` (в `%LOCALAPPDATA%\Stalker2\Saved\Logs\` или в папке краша
  `%LOCALAPPDATA%\Stalker2\Saved\Crashes\UECC-Windows-…\`) заканчивается так:

  ```
  LogD3D12RHI: Error: GPU crash detected:
      - Device 0 Removed: DXGI_ERROR_DEVICE_HUNG
  ```

  Копия в папке краша в UTF-16: открывай её в Блокноте, а не в программе, которая ждёт UTF-8.
- Просмотр событий Windows → *Журналы Windows* → *Система*: от трёх до пяти ошибок **`nvlddmkm`, Event ID 153**
  (`Error occurred on GPUID: …`) примерно за десять секунд, после чего идёт предупреждение
  **`Display`, Event ID 4101**:
  *Display driver nvlddmkm stopped responding and has successfully recovered.*
  «Видеодрайвер nvlddmkm перестал отвечать и был успешно восстановлен.»

Это **не** та проблема, если в логе стоит `EXCEPTION_ACCESS_VIOLATION` (это обычный вылет игры)
или если зависает весь ПК и его приходится перезагружать.

Как это выглядело здесь: пять вылетов подряд, каждый через 2–10 минут после загрузки сохранения, четыре из них в
**Ростоке**; раньше — один после шести часов игры на Химзаводе. Продажа вещей торговцу и
беготня во время Выброса сначала казались причинами; нет — достаточно было загрузить сохранение и
походить по Ростоку.

## Версии

| | Где наблюдалось |
|---|---|
| Игра | 2.0.6 (Unreal Engine 5.5.4), с DLC |
| Драйвер NVIDIA | 616.92 (тот же сбой GPU наблюдался и в другой игре на Unreal Engine 5 на 616.56 и 616.64) |
| GPU | GeForce RTX 5090 — другие карты не проверялись |

## Исправление: отключить Async Compute

1. Запусти игру и открой **Настройки → Графика → Async Compute**.
2. Поставь **Async Compute** в положение **Выкл.** (Точная формулировка может отличаться в зависимости от языка игры:
   пункт может называться «Асинхронные вычисления».)
3. Примени настройки и перезапусти игру, чтобы изменение действовало с самого начала игрового сеанса.

Это всё — никакие файлы не меняются.

**Побочный эффект:** при выключенном Async Compute текстуры и детали вдали могут мерцать — появляться и
пропадать. Производительность немного падает.

### Как отменить

Верни **Async Compute** в положение **Вкл.**

### Что сбивает фикс

Ничто, кроме тебя самого, его не сбрасывает: это обычная настройка в игре, и она хранится вместе с остальными настройками.

## Экспериментально: оставить Async Compute и отключить только один проход

**Пока не проверено.** Если мерцание мешает, этот вариант оставляет Async Compute включённым и возвращает в
графическую очередь только одну часть работы — отсечение невидимого в основном проходе Nanite, наиболее вероятного виновника.

1. Закрой игру.
2. Открой `%LOCALAPPDATA%\Stalker2\Saved\Config\Windows\` (вставь путь в адресную строку проводника).
3. Создай текстовый файл `Engine.ini` (или открой уже существующий) и добавь:

   ```ini
   [SystemSettings]
   r.Nanite.AsyncComputeMainPassCullingAndBinning=0
   ```

   Если в файле уже есть секция `[SystemSettings]`, добавь только вторую строку под ней.
4. Сохрани, затем **щёлкни по файлу правой кнопкой → Свойства → поставь галочку «Только чтение» → ОК**. Без этого игра
   удаляет файл, прочитав его при запуске.
5. Запусти игру и верни **Async Compute** в положение **Вкл.**

Если игра всё равно вылетает, вернись к простому исправлению выше. Чтобы отменить: сними галочку «Только чтение», удали строку
(или удали файл, если ты создавал его только для этого).

## Помоги найти причину

Если ты поймал этот вылет, эти строки заставят следующий краш-репорт показать, чем занимался GPU в тот
момент (Direct3D 12 «DRED»). Добавь их в тот же `Engine.ini` под `[SystemSettings]`, оставь файл
только для чтения и после вылета ищи строки `DRED:` в конце `Stalker2.log`:

```ini
r.GPUCrashDebugging=1
r.GPUCrashDebugging.Breadcrumbs=1
r.D3D12.DRED=1
```

Они отнимают несколько процентов частоты кадров; убери их, когда закончишь. Драйвер NVIDIA также пишет
собственный дамп сразу после вылета: `C:\ProgramData\NVIDIA Corporation\nvtopps\nct\NV_dmp_<N>.nv-gpudmp`
и рядом `.json`. Слотов с номерами несколько — скопируй самый новый до следующего
вылета.

## Состояние

- **Async Compute выключен:** ни одного вылета в первом игровом сеансе после изменения, в том же месте, где
  игра вылетала каждые 2–10 минут. Один сеанс — многообещающе, но за недели пока не доказано.
- **Вариант с `r.Nanite…=0`:** в игре ещё не проверялся.
- **Первопричина:** сужена, не доказана. См. [как это нашли](docs/how-it-works.ru.md).

## Вопросы

**Сломана ли моя видеокарта?** На этом ПК стресс-тесты и тест памяти прошли чисто, а вылет привязан к месту в игре,
а не к нагрузке или температуре. Это указывает на программную часть — игру, драйвер или их сочетание, а не на
выходящую из строя карту. Это не доказывает, что карта безупречна.

**Вызывают ли это Frame Generation или Reflex?** Не напрямую: сбой произошёл внутри собственного списка
команд отрисовки игры, а не на этапе генерации кадров. См. технический разбор.
